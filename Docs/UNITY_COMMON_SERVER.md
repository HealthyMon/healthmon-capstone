# Unity 공용 서버 연결

Unity 프로젝트는 `Client/HealthMonUnity`이며 기본 씬은 `MainARScene`입니다.
서버 실행은 [공용 서버 안내](COMMON_SERVER.md)를 따릅니다.

## 연결

1. 지정된 Unity 버전으로 프로젝트를 열고 `MainARScene`에서 Play를 시작합니다.
2. 우상단 설정 버튼으로 **COMMON SERVER** 개발 패널을 엽니다.
3. API 주소와 사용자 토큰, 펫 ID를 입력하고 연결합니다. 펫 ID를 비우면 소유한 첫 펫을 선택합니다.
4. 서버 인스턴스·소유자·펫 검증 후 홈의 레벨·EXP·Coin·친밀도·활동성을 서버 값으로 표시합니다.

데스크톱 환경변수는 `API_BASE_URL`, `HEALTHMON_USER_TOKEN`, `HEALTHMON_PET_ID`입니다.
토큰은 비직렬화 런타임 필드에 보관합니다.
Android 에뮬레이터의 호스트 주소는 `10.0.2.2`, 실제 휴대폰은 서버 PC의 LAN/HTTPS 주소를 사용합니다.

서버와 계정별로 마지막에 연결한 펫 ID를 저장합니다. 다음 연결에서 펫 ID를 비워 두면,
현재 계정의 소유 목록에 남아 있는 마지막 펫을 다시 선택합니다. 인증 토큰은 저장하지 않습니다.

## 홈·진화·펫 AR

홈에서는 연결한 펫의 인증된 3D 모델을 카메라 앞에 표시합니다. AR 평면 터치 없이도
PC와 휴대폰의 홈에서 펫을 볼 수 있으며, 계정이나 펫이 바뀌면 이전 펫의 표시는 숨깁니다.
상태 보기는 공용 서버의 성장·성격 수치를 표시합니다.

홈 오른쪽의 진화 버튼은 서버의 목표 단계가 현재 모델 단계보다 높을 때 사용할 수 있습니다.
v2.2 규칙의 진화 기준은 Lv.10·20·30이며, 진행 중 재시도는 기존 요청 ID를 유지합니다.
3차 진화까지 완료한 펫은 완료 상태를 표시합니다.
진화 중 앱을 재시작해도 같은 요청을 이어서 조회하며, 현재 공개된 펫 모델을 먼저 복원합니다.

하단 **펫 AR**은 음식 촬영과 별도의 화면입니다. PC에서는 펫 미리보기와 안내를 표시합니다.
휴대폰에서는 AR이 인식한 바닥을 터치해 배치하며 UI 터치는 배치 요청에서 제외합니다.
메뉴 전환과 PC 표시는 Unity Editor에서 확인했으며 실제 휴대폰의 바닥 인식은 별도 검증 대상입니다.

## 퀘스트 탭

하단 **퀘스트**에서 서버의 실제 목록·진행도·EXP·코인 보상을 확인합니다.
기본 퀘스트 보상은 서버가 완료를 확인하면 자동 지급하며, 로컬 보상 버튼으로 추가 지급하지 않습니다.
선택 제안은 스크롤 영역에 실제로 표시된 행의 표시 확인이 끝난 뒤 수락·거절할 수 있습니다.
새로고침과 주기 조회로 서버 상태를 갱신하며 계정·펫이 바뀌면 이전 목록을 제거합니다.
일간 퀘스트는 서버가 정한 한국 시각의 오늘, 주간 퀘스트는 이번 주 항목을 표시합니다.
지난 날짜의 기록은 서버에 유지하며 현재 미완료 목록에 섞지 않습니다.
식사 퀘스트는 **아침·점심·저녁 + 실제 섭취량 확인** 기록을 집계합니다.
음식 확인 화면 위쪽에서 식사 구분을 직접 선택하고 실제 먹은 g과 확인 체크를 입력합니다.
간식은 식사 퀘스트 횟수에 포함되지 않으며, 섭취량이 확인된 경우 기록 EXP에 반영합니다.
섭취량을 모르면 비워서 기록할 수 있지만 식사 퀘스트·기록 EXP에는 반영되지 않는다는 안내를 표시합니다.
영양 정보가 없는 것과 섭취량이 확인되지 않은 것은 별개의 조건입니다.

## Unity 브랜치 통합 (2026-10-23)

`feature/unity`의 `866defe` 씬·프리팹·장신구·웨어러블 화면과 `feature/dev`의 공용 서버 권한·기록 동기화를 통합했습니다.
AR 터치·이동은 생성된 GLB의 시각 요소에 연결하고 원래 슬라임 렌더러는 숨깁니다.
미리보기 카메라의 중복 AudioListener를 비활성화했습니다. 빌드 백업 폴더는 Git에 포함하지 않습니다.
Android JNI는 `com.healthmon.capstone.mobile.unity.HealthMonUnityBridge`이며 AAR은 병합한 소스로 다시 빌드했습니다.

검증: 서버 766 통과·1 제외, Android 플러그인 단위 8 통과·에뮬레이터 5 통과,
휴대폰 테스트 앱 에뮬레이터 1 통과, 워치 Kotlin 컴파일 성공. Unity 실제 서버 모델 검증 87항목과
퀘스트 행·펫·AR 메뉴·터치·로컬 보상 차단 및 진화 중 재시작 후 기존 모델 복원 검증을 통과했습니다.
실물 휴대폰 AR 추적·실물 워치 페어링·생성 모델별 장신구 부착 위치는 별도 확인 대상입니다.

## 새 테스트 펫으로 시작

연결한 서버 환경이 `test`인 경우 **관리자 → 새 테스트 펫으로 시작**을 사용할 수 있습니다.
새 펫은 서버의 기본 초기종과 레벨 1 상태로 생성하고 즉시 선택합니다.
기존 펫·기록·모델은 삭제하지 않습니다. 대화나 진화 요청이 진행 중이면 먼저 해당 요청을 마칩니다.
공용 서버 모드에서는 기존 로컬 스탯·보상 조작 UI 대신 이 안내와 새 펫 시작 기능을 표시합니다.

## 화면 흐름

- **대화:** 서버의 현재 스탯·기억·성격 축을 전달하고 응답을 표시합니다. 긴 문구는 버블 안에서 스크롤합니다.
- **음식:** 사진 분석 후 반환 후보를 선택하고 실제 섭취량, 채소·과일 양, 식사 구분을 확인해 저장합니다.
- **운동:** WearableScene에서 기록·실시간 상태를 표시하고, 본인 기록으로 확인한 항목을 서버에 동기화합니다.
- **퀘스트:** 서버 목록과 보상을 사용합니다. 선택 제안은 표시 확인 후 수락·거절합니다.
- **진화:** 서버 작업 상태를 조회하고 인증된 GLB를 기존 AR 배치 루트에 로드합니다.

## 상태와 재시도

상태는 `healthmon.v2.2` 계약과 `state_version`을 검사합니다.
서버·계정·펫과 연결 세대가 다른 응답은 현재 화면에 적용하지 않습니다.
대기 중인 대화·진화는 같은 요청 ID로 재시도합니다.
동일 서버·계정·펫에서 토큰을 갱신할 때는 패널의 재인증 기능으로 요청 범위를 유지합니다.
운동 업로드는 Android WorkManager에서 대화 요청과 독립적으로 실행합니다.

## 모델과 Android 의존성

모델은 최신 서버 상태의 stage·revision·해시와 일치하는 자산을 표시합니다.
초기종과 진화 결과는 공용 서버의 인증된 같은 origin에서 다운로드하며 SHA-256을 확인합니다.
GPU 주소와 AI 서비스 토큰은 Unity에 전달하지 않습니다.

Android 빌드는 `Assets/Plugins/Android/mainTemplate.gradle`의 전이 의존성을 사용합니다.
AAR 빌드와 동기화 설정은 [Android 연동](../Wearable/Android/HealthMonWatch/docs/unity-plugin-integration.md)을 따릅니다.
Unity 테스트는 [Play 테스트 안내](../Client/HealthMonUnity/Tests/NATIVE_E2E.md)를 참고합니다.
