# 로컬 실행 분리와 더미 정리 — 1차

기준: `origin/develop`의 `958a8b52` (2026-11-11, 상점 구현).
1차 작업 브랜치: `refactor/local-runtime`. 이후 `feature/poseai`에 이 변경과 서버 상점·Unity 운동 화면·Android 지원을 함께 반영했다.
현재 실행은 `Start/Stop-HealthMon.cmd -Target Backend`(API·DB)와 `Start/Stop-HealthMon.cmd -Target AI`(대화·음식·3D·관절) 두 그룹이다.
아래 1차 기록 이후의 운동 구현·검증 범위는 `Ai/Pose/README-WINDOWS.md`, Android 실기기 미검증 항목은 `Ai/Pose/README-ANDROID.md`를 따른다.

## 변경한 동작

- `Start/Stop-HealthMon.cmd -Target Backend`: API·DB만 관리한다. AI 모델이 없어도 백엔드를 실행한다.
- `Start/Stop-HealthMon.cmd -Target AI`: 대화·음식·3D 그룹만 관리한다. 일반적인 온·오프에서 API 설정을 바꾸지 않는다.
- `Start/Stop-HealthMon.cmd`: 전체 편의 실행을 유지한다. AI 실패 후에도 준비된 백엔드를 유지한다.
- AI 최초 연결 설정 후 백엔드를 한 번 시작해야 한다. 이후 AI 재시작은 백엔드 재시작을 요구하지 않는다.
- 같은 체크아웃의 AI supervisor는 파일 잠금으로 하나만 실행한다. 생성 중 종료 요청은 현재 작업 완료를 기다리고 대화 모델 재로드를 생략한다.
- DB·API 준비 상태와 AI 상태를 분리한다. 인증된 `/health/dependencies`와 Unity 개발 설정에서 기능별 실제 관측 상태를 표시한다.
- Unity 새 설치는 서버 모드, 기본 주소는 `127.0.0.1:18092`다. 기존에 오프라인을 선택한 에디터는 `Tools > HealthMon > Offline Play > 3. 서버 모드로 전환` 후 Play를 재시작한다. `HEALTHMON_LOCAL_DEMO=1` 환경 변수가 있으면 그것도 해제한다.
- 오프라인 전환 메뉴는 PlayerPrefs 설정만 바꾸며 소스 코드를 문자열 치환하지 않는다. 데모 UI는 기존 설치 메뉴에서 명시적으로 설치한다.

삭제한 것은 백업 내용과 대응 메타 **14개 파일, 약 6.4MiB**다. Unity가 빈 폴더를 다시 만들 때 GUID가 바뀌지 않도록 폴더 메타 4개는 원본으로 유지했다.
삭제 전 추적된 소스·씬·설정에서 백업 GUID와 파일명 참조를 조사했고 외부 참조가 없었다.
실제 빌드 씬은 BootScene·MainARScene·WearableScene이다. 삭제한 과거 사본은 Git 이력에서 복구할 수 있다.

다음 항목은 필요성이 있어 유지했다.

- `Server/tests`, `Server/local_probe/test_*`의 fixture/mock: 장애·재시도·계약 검증용이며 실제 AI 출력이 아니다.
- 서버의 mock 모드: test 환경·허용된 테스트 계정 범위에서만 사용하는 회귀 검증 기능이다.
- 최초 로컬 실행의 개발 계정·기본 펫 seed: 로그인·연결 확인에 필요하며 이미 있는 설정과 기록을 대체하지 않는다.
- 기본 캐릭터·상점 아이콘·실제 모델 자산: 표시 또는 추론에 사용한다.
- AI migration report와 과거 실험 기록: 현재 실행 상태의 근거로 사용하지 않으며, 단순히 오래됐다는 이유로 삭제하지 않았다.
- 예전 UI 스타일 설치 도구: 씬 직접 참조만으로 삭제 여부를 결정할 수 없어 유지했다.

### 실제 AI 추론과 독립 실행

- 현재 클론의 별도 native 백엔드(API 18092 / DB 55445)와 AI 그룹(18090/18091/18093/18094)을 기동했다. 인증값·PC별 경로는 Git에서 제외된 `.runtime`에만 보관했다.
- Qwen 대화 실제 생성 2건과 동일 요청 ID 재호출의 멱등성, BGE-M3 임베딩 1,024차원, 저장소 음식 사진의 실제 Vision 추론을 확인했다. 생성 답변을 더미 응답으로 대체하지 않았다.
- 실제 이미지 생성 → TRELLIS 3D 재구성 → 리깅 → 검증 → 서버 게시를 통과했다. 1단계 GLB는 57,759,388바이트이며 SHA-256은 `84366606196be61a25adcc3825ebdd6c44e6ffd97c7d6eeb8e835d1a25fd3f2a`다. 생성 자격을 만들기 위한 레벨 10 기록만 격리된 테스트 데이터다.
- 생성 중 AI 종료 요청은 작업 완료를 기다린 뒤 종료했다. AI를 끈 동안 API 프로세스와 펫 기록이 유지됐고 대화는 503을 반환했다. AI 재시작 후 같은 요청 ID 재시도는 실제 응답을 받았으며 중복 호출 결과도 같았다.
- 첫 Docker 작업은 로컬 엔진의 WSL 연결 오류로 실패했다. 엔진 재시작 후 새 테스트 펫에서 실제 파이프라인을 통과했다. 실패한 진화 작업을 같은 펫·단계에서 다시 요청하는 기능은 별도 개선이 필요하다.

실행 증거는 저장소 옆 `healthmon-validation`의 `inference.json`, `evolution.json`, `lifecycle.json`, `server-tests.txt`에 있다.

### 실제 실행에서 수정한 결함

- Vision: Git LFS 파일이 실제 바이너리로 내려온 정상 클론에서 텍스트로 해석하다 실패했다. 고정된 가중치 manifest와 SHA-256/크기를 검사하도록 수정했다.
- AI 상태: Windows가 상태 JSON을 읽는 순간 파일 교체가 거부되면 heartbeat 스레드가 종료됐다. 짧은 제한 재시도 후 다음 heartbeat로 복구하게 했다.
- 대화 화면: 비활성 AR 말풍선 컴포넌트의 `Awake`와 투명 CanvasGroup 때문에 고정 답변이 숨고 스크롤 입력이 막혔다. 고정 답변의 표시·입력을 복구하고 중복된 AR 말풍선을 숨겼다.
- 모델 표시: 스킨 메시 측정에서 Transform 배율을 중복 적용해 설정 높이 0.35m가 약 1.1667m로 표시됐다. `BakeMesh`의 배율 보정을 사용해 실제 높이 0.35000005m를 확인했고, 설정 높이와의 일치 검사도 추가했다. [Unity BakeMesh 문서](https://docs.unity.com/en-us/engine/6000.3/script-reference/unityengine/skinnedmeshrenderer/bakemesh)
- 검증 도구: 초기 자동 로그인 완료를 기다린 뒤 테스트 펫으로 전환하고, 홈과 AR 월드가 분리된 씬에서 실제 AR 탭을 연 뒤 모델을 검사하게 했다. C# 검사에는 Windows 명령 길이 제한을 피하는 response 파일을 사용했다.

## 2차: 서버 상점과 게임 코인 연결 (2026-11-15)

사용자가 2번 구현을 명시적으로 요청해 진행했다. 기본 슬라임 및 생성 모델 교체는 이번 범위에서 제외한다.

- 기존 카탈로그 54개를 서버의 `shop_catalog.json`으로 등록했다. 클라이언트가 보낸 가격으로 결제하지 않으며, 화면에서 확인한 가격과 서버 가격이 달라지면 구매를 거절한다.
- `GET /shop/catalog`, `GET /pets/{pet}/shop`, `POST /pets/{pet}/shop/purchases`, `PUT /pets/{pet}/shop/character`를 제공한다. 인증·펫 소유권 확인은 모든 개인 상태 요청에 적용한다.
- 지갑은 **펫별**이다. 기존 활동·퀘스트 보상 합계에서 실제 구매 지출을 뺀 잔액을 홈·퀘스트·상점이 함께 사용한다. 구매·보유 등록·요청 영수증·상태 갱신은 하나의 DB 트랜잭션으로 저장한다.
- 활동 보상과 구매가 같은 펫 잠금을 사용한다. 같은 요청 ID 재전송과 다른 ID로 이미 보유한 상품을 다시 구매하는 경우 모두 추가 차감하지 않는다. 동일 ID의 상품·가격·작업 변경은 거절한다.
- Unity는 서버 모드에서 어댑터를 자동 생성한다. 서버 가격은 실행 중 복사한 카탈로그에 반영해 저장된 씬·상품 에셋을 수정하지 않는다. 서버 잔액과 보유 목록을 확인한 후에만 구매 성공을 표시한다.
- 상점 통신은 대화·음식 추론과 별도 요청 경로를 사용한다. 응답 유실 시 요청 ID와 확인 가격을 서버·계정·펫별로 보존하며, 재접속 때 서버 보유 목록과 대조한다. 인증 토큰은 이 저장 정보에 포함하지 않는다.
- 구매한 장신구 종류는 꾸미기 화면에 보유 상태로 반영한다. 서버 모드에서는 오프라인 저장의 무료 해금 정보가 섞이지 않고, 재접속 때 서버 구매 목록에서 복원한다. 개별 3D 상품 외형과 장착 상태의 서버 저장은 별도 후속 범위다.
- 캐릭터 선택 ID는 서버에 저장하고 상점에서 `선택됨`으로 표시한다. 실제 홈 모델 변경·재학습은 보류한다.
- `010_shop.sql`은 기존 테이블을 삭제하지 않고 상점 테이블을 추가한다. 네이티브 로컬 백엔드도 재시작 시 누락된 migration을 적용한다. Docker는 기존 migration 서비스를 사용한다.
