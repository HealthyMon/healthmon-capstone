# 전투 능력치와 식습관 효과 — balance v1

## 원인과 근거

[전투 PR #15](https://github.com/HealthyMon/healthmon-capstone/pull/15)는 “추후 헬스몬 스탯 변환 연동 필요”를 남겼다.
2026-11-22에 공개된 브랜치, PR 설명/관련 코드와 저장소 문서를 조사했으나 완성된 전투 변환식은 발견하지 못했다.

기존 AdventurePlayerStats는 HP/ST를 씬의 BattleUnit에서 가져오고 공격·방어·저항·속도·행운은 자체 Inspector 값(3/4/5/6/5)을 사용했다.
서버/로컬 펫 레벨·생활 스탯을 읽는 연결이 없어서, 관리자 값 저장 여부와 무관하게 전투는 그대로였다.
상태 보기에는 생활 점수만 표시하고 실제 전투 능력치는 표시하지 않았다.

이 문서의 **능력치 수식과 전투 효과 배율은 이번에 추가한 게임 밸런스 v1**이다.
이미 존재하던 서버의 생활 기록 점수, EXP/코인 지급, 식사 판정과 진화 해금 규칙은 바꾸지 않는다.
밸런스 수치는 추후 플레이 테스트에서 조정할 수 있다.

### 규칙 출처와 상태창 연동 (2026-11-24)

- **팀원이 구현한 전투 규칙은 이미 존재한다.** `builtmilk`의 [PR #19](https://github.com/HealthyMon/healthmon-capstone/pull/19) 원본 커밋 `edfeae069`에는 ATB 행동 게이지, 물리·마법 피해, 행동별 ST 소비, 대기·승리 시 ST 회복 등이 구현되어 있다. Inspector에서 조정 가능한 기본값도 포함한다.
- 별도로, [PR #15](https://github.com/HealthyMon/healthmon-capstone/pull/15)는 **생활 스탯을 전투 능력치로 변환하는 연결**을 후속 작업으로 명시했다. PR #19 당시 `AdventurePlayerStats`는 HP/ST를 `BattleUnit`에서, 나머지 능력치를 Inspector 설정값에서 가져왔다.
- 이 문서의 `PetCombatStats` 생활→전투 계산식은 이후 통합 커밋 `9733db0b1`에 추가한 밸런스 v1이다. 기존 팀원의 전투 진행 규칙과 구분하며, 팀원이 확정한 변환식으로 표시하지 않는다.
- 새 레이더 상태창은 현재 전투에서 사용하는 계산 결과를 그대로 표시한다. 생활 점수 6축, 에너지 균형, 최대 HP/ST, 공격·방어·저항·속도·행운, 행동 속도·ST 회복 배율을 보여준다. UI 변경은 전투 수식이나 운동·식사 보상을 수정하지 않는다.
- 상태창의 HP/ST는 **최대치**다. 탐험 중 소비한 현재 HP/ST와 혼동하지 않도록 화면에도 최대치로 명시한다.

## 값의 전달

- 온라인: 관리자 테스트 API 또는 일반 운동·식사·대화/퀘스트의 서버 응답 → CommonServerConnection.LatestState → PetCombatStats.
- 상태 보기와 관리자 결과 요약은 같은 PetCombatStats를 표시한다.
- 일반전·정예전은 전투 직전 최신 결과를 AdventurePlayerStats에서 BattleUnit으로 복사한다.
- 전투 중에는 스냅샷을 고정한다. 도중에 받은 변경은 다음 전투부터 적용한다.
- 같은 펫의 레벨/능력치가 바뀌면 현재 HP/ST 비율을 유지한다. 새로 고침으로 완전 회복하거나 부활하지 않는다.
- 전투 종료 때는 현재 HP/ST만 탐험으로 가져온다. 전투 중 버프를 영구 성장 수치로 역저장하지 않는다.
- 다른 서버·계정·펫으로 바뀌면 별도 탐험 자원 상태로 초기화한다.
- 처음 접속하기 전에는 Inspector 샘플값으로 서버 모드 전투를 시작하지 않는다.
- 오프라인은 선택된 펫의 로컬 레벨/생활 기록을 사용하고 씬 이동 전에 스냅샷을 보관한다. 로컬에 없는 영양·에너지 점수는 중립값(50/0)을 사용한다.

## 기본 계산

L = 레벨(1~30), U = 상체, D = 하체, N = 영양, A = 활동성, F = 친밀도, I = 주도성.
생활 점수는 0~100, 에너지 균형 E는 -100~100이다. g = L - 1.

| 능력치 | 체형 효과 전 수식 | 용도 |
|---|---|---|
| 최대 HP | 100 + 8g + 0.6(N-50) | 체력 |
| 최대 ST | 20 + 0.3g + 0.12(A-50) | 공격/스킬/이동 자원 |
| 공격 ATK | 10 + 2g + 0.16(U-50) | 기본 공격·스킬 피해 |
| 방어 DEF | 5 + g + 0.10(D-50) | 물리 피해 감소 |
| 저항 RES | 5 + g + 0.10(N-50) | 마법 피해 감소 |
| 속도 SPD | 5 + 0.05g + 0.06(D-50) + 0.04(A-50) | 행동 게이지 충전 |
| 행운 LUK | 5 + 0.02g + 0.06(I-50) + 0.02(F-50) | 치명타 확률 |

체형 배율을 적용한 뒤 정수 능력치는 0.5에서 올림한다.
HP·ST·ATK·SPD는 최소 1, DEF·RES·LUK는 최소 0이다.
ST는 소수 값을 유지한다. NaN/무한대와 범위 밖 점수는 거절한다.

모든 생활 점수가 50, E=0일 때:

| 레벨 | HP | ST | ATK | DEF | RES | SPD | LUK |
|---|---:|---:|---:|---:|---:|---:|---:|
| 1 | 100 | 20 | 10 | 5 | 5 | 5 | 5 |
| 10 | 172 | 22.7 | 28 | 14 | 14 | 5 | 5 |
| 30 | 332 | 28.7 | 68 | 34 | 34 | 6 | 6 |

물리 피해 = max(1, 공격 - 방어), 마법 피해 = max(1, 공격 - 저항).
플레이어와 적 모두 치명타 확률 = min(25%, max(0, LUK)%).
치명타는 방어/저항을 계산한 최종 피해의 1.5배이며 최소 피해 1을 유지한다.

## 식습관·체형

서버 v2.2 evolution_profile의 분기 순서와 기준을 재사용한다.
S = (U+D)/2. 아래 표의 위쪽 조건이 먼저 적용된다.

| 조건 | 전투 체형 | 추가 효과 |
|---|---|---|
| E≥30, S<45 | 비만형 | HP ×1.20, DEF ×1.10, 행동 속도 ×0.50 |
| E≤-30, S≥65 | 마른 운동형 | HP ×0.95, 행동 속도 ×1.15, ST 회복 ×0.85 |
| E≤-30 | 마른형 | HP ×0.85, ATK ×0.90, 행동 속도 ×1.10, ST 회복 ×0.75 |
| E≥30, S≥65 | 벌크 운동형 | HP ×1.15, ATK ×1.10, 행동 속도 ×0.90 |
| E≥30 | 통통형 | HP ×1.10, 행동 속도 ×0.80 |
| S≥65, U-D≥15 | 상체 발달형 | ATK ×1.10 |
| S≥65, U-D≤-15 | 하체 발달형 | SPD ×1.10 |
| S≥65, N≥60 | 균형 운동형 | 기본 수식 적용 |
| S≥65 | 운동형 | 기본 수식 적용 |
| S≥45 | 일반형 | 기본 수식 적용 |
| 나머지 | 운동 부족형 | 기본 수식 적용 |

영양 점수 자체의 ST 회복 배율은 N≥60이면 ×1.15, N<40이면 ×0.75, 나머지는 ×1이다.
체형의 ST 회복 효과와 곱한다. 예: 마른형 + 영양 부족은 회복 ×0.5625.

현재 전투는 고정 턴제가 아닌 ATB 방식이다.
게이지 초당 충전량 = (20 + 3×SPD) × 행동 속도 배율, 준비 기준은 100.
비만형은 **같은 SPD의 기본 체형에 비해 행동까지 걸리는 시간이 2배**다.
적 SPD와 행동 연출 시간이 달라지므로 모든 적을 상대로 “적이 정확히 2번 행동하면 1번 행동”을 보장하는 규칙은 아니다.

효과는 현재의 서버 점수로 판정한다. 외형 GLB가 다시 생성될 때까지 기다리지 않는다.
식사 한 번의 원시 칼로리를 직접 전투에 더하지 않으며, 서버에서 확인·계산한 영양/에너지 균형을 사용한다.
사용자 실제 건강에 대한 판정이 아닌 게임 규칙이다.

## 검증

기존 컴파일 검사에 CombatStatsChecks를 포함했다.
서버 evolution_profile로 생성한 경계 사례 3,402개와 C# 체형 판정을 비교하며,
레벨 1/30, 상체/하체·영양 효과, 반속도, 유효 범위/잘못된 입력을 검사한다.

서버 성장·식사 규칙과 관리자 저장·복원 검사 175개를 통과했다.
C# 전투 계산·서버 체형 경계 비교 3,481개, 기존 DTO/권한 검사, Editor/Android 컴파일을 통과했다.
최종 30레벨 버전의 휴대폰 화면·전투 조작 확인은 아직 하지 않았다.

최대 레벨은 30이다. 서버 성장 계산은 누적 EXP 원장을 보존하면서 30레벨에서 멈추며,
관리자 입력도 1~30만 허용한다. 레벨 상한과 생활 점수 상한(100)은 서로 다르다.
