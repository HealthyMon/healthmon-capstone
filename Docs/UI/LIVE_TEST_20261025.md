# feature/ui 실제 재생 테스트 · 2026-10-25

Unity 6000.4.6f1의 MainARScene을 직접 재생하고, 기존 로컬 테스트 서버에 연결했습니다. 기존 PostgreSQL·계정·펫·모델을 재사용했습니다.

## 확인한 동작

| 항목 | 결과 |
| --- | --- |
| 컴파일 및 재생 | 재생 가능, 테스트 구간에서 C# 컴파일 오류·앱 예외 없음 |
| 시작 → 캐릭터 선택 → 홈 | 버튼으로 이동, 실제 저장 캐릭터 목록과 3D 미리보기 표시 |
| 저장된 캐릭터 | 레벨 20, 저장된 2차 진화 GLB를 서버에서 불러와 표시 |
| 설정·관리 | 캐릭터·운동·퀘스트·연결 4개 탭 열림, 각 탭의 주 버튼 유지 |
| 설정 닫기 | 홈 복귀 후 저장 캐릭터 표시 유지 |
| 퀘스트 화면 | 서버의 일일·주간 퀘스트 및 진행도 표시 |
| 대화 전송 | Unity 입력칸에 일반 테스트 문장을 입력하고 보내기 클릭, 클라이언트 ChatDisplayed 및 fallback=False 확인 |
| 대화 → 퀘스트 | 일일 대화 퀘스트 완료 확인. 테스트 전후 EXP 0 → 45, 코인 10 → 20 |
| 음식 분석 API | 프로젝트의 food.jpg 샘플을 기존 API에 전송, HTTP 200, real 분석 후보 3개 수신 |
| 기존 데이터 | 확인 시점의 식사 기록 4건, 선택된 기존 펫 및 2차 모델 유지 |

## 테스트 중 보정

별도 UI 작업본에는 기존 설치의 비공개 서버 연결 정보가 없었습니다. 로컬 전용 `editor-connection.json`을 지원하도록 에디터 연결 복원 경로를 추가하고, 같은 서버·펫으로 자동 연결되는 것을 재생에서 확인했습니다. 서버 설치용 프로필은 변경하지 않았습니다.

## 남은 검증 및 관찰

- 음식 분석은 API 응답까지 확인했습니다. 이번 실행에서 UI의 음식 후보 선택·기록하기·동일 사진의 새 식사 저장까지는 확인하지 않았습니다.
- 운동 테스트 기록 추가, 성격 값 적용, 새 펫 생성은 기존 상태에 임의 데이터를 추가하지 않도록 누르지 않았습니다.
- 도감·꾸미기·웨어러블·AR의 전체 런타임 경로와 모바일 키보드, 안전 영역, 휴대폰·워치 실기기 연결은 이번 수동 실행에서 확인하지 않았습니다. 이전 오프라인 캡처 결과와 구분해야 합니다.
- 설정의 슬라이더 채움 영역이 두꺼운 사각형으로 보이는 시각적 문제가 관찰됐습니다. 값 변경·서버 적용 여부와 별개로 표시를 추가 정리할 필요가 있습니다.
- 사용자 입력이 감지된 뒤에는 화면 조작을 멈추고 API·로그 확인을 진행했습니다. 서버는 실행 상태로 유지했습니다.

이 결과는 모든 기능에 대한 전체 통과 판정이 아닙니다. 이번에 직접 재생하거나 API로 확인한 범위를 위 표에 기록했습니다.
