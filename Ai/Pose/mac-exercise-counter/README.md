# Local Motion — Mac 로컬 운동 카운터

기존 RTMPose-L Body 17 (높이×너비 384×288) + YOLOX-tiny HumanArt를 사용하는 PySide6 앱입니다. rtmlib 0.0.16 / ONNX Runtime 1.31.1, 기본 CoreML + CPU 경로를 유지합니다. 2026-11-06 수정에서는 모델·패키지·가상환경을 교체하거나 추가 학습하지 않았습니다. 추론은 로컬이며, 앱은 카메라 영상을 저장하거나 외부로 전송하지 않습니다. 맨손 컬도 셉니다.

## 실행

Apple Silicon Mac에서 이 폴더로 이동한 후 실행합니다. 최초 설치에는 인터넷 연결과 Xcode Command Line Tools(`xcode-select --install`)가 필요합니다.

```bash
./setup.sh
./run.sh
```

`Local Motion.app`을 더블클릭해도 됩니다. 기본 실행에는 자동 종료가 없습니다. 프로젝트를 이동했다면 `.venv/bin/python scripts/build_launcher.py`로 런처를 다시 만드세요.

운동과 카메라를 선택하고 **시작**하세요. **동영상 열기**로 로컬 영상도 처리합니다. 동영상 검사 후에는 카메라 메뉴에서 사용할 카메라를 다시 선택하고 시작하세요.

## 필요한 촬영 범위

| 운동 | 필수 관절 | 동작과 제한 |
|---|---|---|
| 덤벨 컬 | 각 팔의 어깨·팔꿈치·손목 | 한쪽 팔만 보여도 해당 팔을 독립적으로 셉니다. 얼굴·반대쪽 어깨·골반·무릎·발목은 필요하지 않습니다. |
| 스쿼트 | 같은 쪽 골반·무릎·발목 | 어깨와 얼굴은 필요하지 않습니다. 한쪽 다리만 보일 때 정면 영상이라면 **스쿼트 시점 → 정면**을 선택하세요. 자동 시점 판별은 양쪽 골반을 이용합니다. |
| 팔굽혀펴기 | 보이는 쪽 어깨·팔꿈치·손목 | 사용자가 팔굽혀펴기를 선택한 상황에서 팔의 완전한 반복을 셉니다. 하체가 없으면 **전신 자세 평가 보류**를 표시합니다. 팔 반복만으로 올바른 전신 자세를 확인했다는 뜻은 아닙니다. |

팔이나 다리를 편 준비 자세를 잠시 유지한 뒤 운동하세요. 굽힌 상태로 등장한 첫 미완료 반복은 세지 않습니다. 움직이는 동안 필수 관절이 화면 안에 남도록 여백을 두세요. 무릎만 보이거나, 굽힐 때 팔꿈치가 잘리는 영상은 억지로 세지 않습니다.

스쿼트·팔굽혀펴기는 선택된 신체의 좌우를 고정합니다. 신뢰도 순서가 바뀌어도 반복 도중 다른 쪽으로 바꾸지 않습니다. 변경하려면 **대상 재선택** 후 준비 자세부터 시작하세요. 좌우는 화면 기준이 아니라 본인 신체 기준입니다.

필수 관절 가림은 해당 팔/운동의 진행 중 반복만 취소합니다. 누적 횟수는 유지합니다. 일시정지·운동 변경·대상 변경·수동 영역 변경·스쿼트 시점 변경도 진행 중 반복을 취소하고 준비 자세를 다시 확인합니다. **횟수 초기화**는 현재 운동의 횟수를 초기화합니다. 입력 종료 후 새로 시작하면 새 세션입니다.

## 탐지와 수동 영역

기본은 한 명을 자동 선택한 뒤 고정 추적합니다. 여러 명이면 영상에서 셀 사람을 클릭하세요. 짧은 손실은 위치·외형이 일치하는 한 명을 확인한 경우에만 복구합니다. 별도 사람이 관측된 뒤 대상을 잃었다면 자동 복구하지 않고 같은 사람을 다시 선택해야 합니다. 오래 잃거나 사람이 겹치면 **대상 재선택** 또는 보이는 사람 영역 클릭이 필요합니다.

부분 촬영에서 탐지 박스가 안 잡히면 **사람 영역 직접 지정**을 누르고 영상에서 한 사람의 측정 부위를 드래그하세요. 필요한 관절 전체와 움직일 여백을 포함하되 배경만 지나치게 넓게 지정하지 마세요. 지정한 영역을 기존 RTMPose에 직접 입력합니다. 탐지 실패만으로 전체 화면을 자동으로 사람 영역으로 취급하지 않습니다.

수동 영역에서도 신뢰도·경계·상태 머신을 동일하게 검사합니다. 필수 관절이 모두 사라진 상태가 지속되거나 영역 안에 여러 사람이 탐지되면 잠기며, 다시 영역을 지정해야 합니다. 고정된 수동 영역은 동일 인물 재식별 기능이 아닙니다. 한 사람만 사용하세요. **대상 재선택**으로 자동 탐지 모드에 돌아갑니다.

## 인식 진단

**인식 진단** 버튼에서 원본 탐지 박스 수·같은 대상 중복 제외 수와 경과 시간, pose 실행 여부, 필수 관절별 신뢰도/경계 유효성, 사용 중인 좌우, 준비·굽힘·복귀 상태, 중단 이유, 각도와 FPS를 확인할 수 있습니다. 일시정지한 파일에서는 마지막 관측 시각을 표시하며 해당 좌표로 카운팅하지 않습니다. 가려진 관절은 평활화 좌표를 지우고, 다시 나타났을 때 새 관측부터 시작합니다.

## 설정

`config.json`을 수정하고 앱을 다시 여세요. 신뢰도 0.45, 기본 굽힘/복귀 각도와 시간 유지 조건은 이번 수정에서 일괄적으로 낮추지 않았습니다. 설정은 이 구현의 공학적 시작값이며 의학적 기준이나 보편적인 운동 정답이 아닙니다.

- `quality`: 신뢰도, 화면/영역 경계 여백, 평활화 시간, 관절 사이 최소 길이. `duplicate_arm_distance_px`는 잘린 반대팔이 보이는 팔과 같은 위치로 추정될 때 중복 관측을 보류하는 거리입니다.
- `timing`: 준비·굽힘·복귀 유지 시간과 최소/최대 반복 시간.
- `squat.*_leg`: 준비 자세에서 **관측된 허벅지+종아리 길이**에 대한 골반 하강/발 이동 비율입니다. 이전 `*_torso` 설정과 단위가 다릅니다. 이전 사용자 설정 파일은 현재 파일을 기준으로 갱신하세요.
- `squat.view`: `auto`, `front`, `side`. UI에서도 선택합니다. 한쪽 다리만으로 정면/측면을 확실히 구분할 수 없어 자동 모드는 양쪽 골반을 확인할 수 없으면 측면 조건을 사용합니다.
- `tracking.duplicates`: 화면 가장자리에 걸친 스쿼트 박스의 겹침/포함 비율, 현재 관절 일치, 직전 대상 관절 연속성 기준입니다. 중복 확인은 이미 선택된 대상에만 적용하며 서로 다른 사람의 겹침 보호를 끄지 않습니다.
- `manual_region`: 최소 지정 영역 크기, 관절 손실 후 잠금 시간, 여러 사람 탐지 판단 범위.

카메라는 최신 프레임 한 개만 추론하며 오래된 프레임을 누적하지 않습니다. 파일은 원래 타임스탬프로 모든 프레임을 처리하므로 처리량이 부족하면 재생이 느려집니다. 화면의 입력→표시 지연은 프레임 수신부터 UI 갱신까지이며 카메라 센서/모니터 광학 지연은 포함하지 않습니다.

CoreML이 실패하면 CPU로 복구하고 원인을 표시합니다. 강제로 CPU를 쓰려면 `./run.sh --provider cpu`. CoreML + CPU는 모든 연산이 GPU/ANE에서 실행된다는 뜻이 아닙니다.

## 카메라 권한과 재설치

첫 카메라 요청을 허용하세요. 거절했다면 **시스템 설정 → 개인정보 보호 및 보안 → 카메라 → Local Motion**을 켜고 다시 여세요. 실행 방식에 따라 터미널/Codex가 표시될 수 있습니다. 마이크 권한은 요청하지 않습니다.

`./setup.sh`는 프로젝트 전용 uv·CPython·가상환경·공식 모델을 설치하고 앱 런처를 빌드합니다. 시스템 Python은 변경하지 않습니다. 설치 완료 후에는 오프라인으로 실행됩니다. 모델 출처/해시/입력 크기는 `models/manifest.json`과 `models/README.md`에 있습니다.

## 검증과 발표 자료

```bash
.venv/bin/python -m pytest -q
./run.sh --video /path/to/exercise.mp4 --exercise pushup --autostart
```

자동 테스트 81개가 통과했습니다. 기존 실제 운동 파일 재생에서 한쪽 다리 정면 스쿼트는 수정 전 2회에서 수정 후 4회, 추적은 145/313프레임에서 313/313프레임으로 바뀌었습니다. 상체 팔굽혀펴기 영상은 5회를 기록했습니다. 화면 갱신 평균은 각각 23.08FPS와 27.21FPS였습니다. 이 수치는 해당 파일 재생에서 측정했습니다. 전신 정면 스쿼트 표본에서는 4회 중 1회를 놓쳤습니다.
