Local Motion 구현 현황 — 발표에 바로 사용할 원고
정리 기준: 2026-11-11 현재 코드 / 수치별 검증 시점은 근거 파일 참조

한 문장 소개
“저희는 사전학습된 사람 탐지·자세 추정 모델을 이용해, 운동에 필요한 관절만 보이는 경우에도 반복 횟수를 계산하는 Mac 로컬 데스크톱 앱을 구현했습니다.”

1. 무엇을 구현했는가
지원 운동은 팔굽혀펴기, 스쿼트, 덤벨 컬입니다. 사용자가 운동을 선택하면 카메라 또는 로컬 영상에서 관절을 추정하고, 완료된 반복과 현재 상태를 화면에 표시합니다. 덤벨 컬은 좌우 팔을 따로 셉니다. 설치 후 추론은 Mac 내부에서 실행하며 카메라 영상은 기본적으로 저장하거나 전송하지 않습니다.

2. 무엇을 사용했는가
사람 영역을 찾는 모델은 YOLOX-tiny HumanArt이고 입력은 416×416입니다. 관절 추정은 RTMPose-L의 Body 17 모델을 사용하며 입력 해상도는 높이 384, 너비 288입니다. 두 모델 모두 공식 사전학습 ONNX 가중치를 사용했습니다. rtmlib 0.0.16의 전·후처리를 활용하고, ONNX Runtime 1.31.1에서 CoreMLExecutionProvider와 CPUExecutionProvider를 명시적으로 구성했습니다. 영상 처리와 추적은 OpenCV, 각도 계산은 NumPy, 데스크톱 화면은 PySide6로 구현했습니다. Python 3.12.16과 프로젝트 전용 가상환경을 사용합니다.

3. 우리가 직접 구현한 핵심
모델을 새로 학습한 것이 아니라 관절 출력을 안정적인 횟수로 바꾸는 로직과 앱을 구현했습니다. 준비 자세를 확인한 뒤 굽힘과 복귀까지 완료해야 한 번을 셉니다. 각도 임계값을 다르게 두고 시간 유지 조건과 평활화를 적용해 작은 떨림이나 중간 동작을 중복으로 세지 않게 했습니다. 관절이나 추적 대상이 사라지면 진행 중 반복만 취소하고 이미 센 횟수는 보존합니다.

4. 부분 촬영 대응
컬은 각 팔의 어깨·팔꿈치·손목만 있으면 독립적으로 측정합니다. 스쿼트는 같은 쪽 골반·무릎·발목으로 측정하고 반복 중 좌우를 바꾸지 않습니다. 한쪽 다리 정면 촬영은 정면 설정을 사용합니다. 팔굽혀펴기는 보이는 팔로 반복을 계산할 수 있지만 하체가 보이지 않으면 전신 자세 평가는 보류합니다. 관절의 신뢰도뿐 아니라 화면 안에 있는 현재 좌표인지를 검사합니다. 탐지기가 부분 신체를 놓칠 때는 사용자가 영역을 직접 지정할 수 있게 했습니다.

5. 실제 오류를 어떻게 개선했는가
한쪽 다리만 보이는 스쿼트에서 같은 사람을 나타내는 박스 두 개가 생겨 추적이 중단되는 문제가 있었습니다. 박스의 겹침뿐 아니라 현재 관절의 일치와 이전 대상의 움직임 연속성을 함께 확인해 같은 대상의 중복만 제외하도록 수정했습니다. 같은 표본 영상에서 기존 2회 중단이 4회 완료로 바뀌었고 313프레임 동안 대상 ID와 사용 다리를 유지했습니다. 실제 다른 사람과 구별할 근거가 부족하면 계속 보류합니다.

6. 검증과 현재 수준
카운터, 가림, 추적 손실, 일시정지, 초기화, 운동 변경, 중복 박스 등을 포함한 자동 테스트 81개를 현재 코드에서 다시 통과했습니다. 실제 영상에서는 상체 덤벨 컬 좌우 각 1회, 한쪽 팔 컬 1회와 반대팔 0회, 한쪽 다리 스쿼트 4회, 상체 팔굽혀펴기 5회를 확인했습니다. 별도의 양팔 컬 표본은 좌우 각 3회였습니다. 실제 영상의 픽셀을 잘라 만든 부분 촬영 영상에서 탐지부터 카운터까지 다시 실행했습니다.
기존 실제 macOS 앱 파일 재생 기록에서 한쪽 다리 스쿼트는 평균 23.08FPS, 상체 팔굽혀펴기는 평균 27.21FPS였습니다. 이는 파일 재생 조건의 화면 갱신 속도이며 실제 카메라 운동에서 같은 성능을 보장한다는 뜻은 아닙니다.
전신 정면 스쿼트 표본에서는 실제 4회 중 3회를 세어 1회 누락이 남아 있습니다. 무릎만 보이거나 필요한 관절이 잘린 경우에는 카운팅을 보류합니다. 다양한 사람·조명·카메라 각도·다인 교차 상황의 일반 정확도는 아직 별도 검증이 필요합니다. 현재는 실시간 로컬 앱과 표본 검증까지 구현한 단계입니다.

질문을 받았을 때
Q. AI 모델을 직접 학습했나요?
A. 공식 사전학습 모델을 사용했습니다. 저희가 구현한 부분은 로컬 실행, 대상 추적, 관절 검증, 반복 상태 머신, 부분 촬영 대응, UI와 검증입니다.
Q. 운동 종류도 자동으로 인식하나요?
A. 현재는 사용자가 세 운동 중 하나를 직접 선택합니다. 자동 운동 분류는 구현 범위에 포함되지 않습니다.
Q. 덤벨도 검출하나요?
A. 현재는 신체 동작을 셉니다. 아령 자체를 검출하지 않으므로 맨손 컬도 셀 수 있습니다.
Q. 정확도는 몇 퍼센트인가요?
A. 일반화된 정확도는 아직 산출하지 않았습니다. 자동 테스트 통과 수와 개별 실제 영상의 관측 횟수를 구분해 제시합니다.
Q. GPU나 Neural Engine을 모두 사용하나요?
A. 실제 활성 provider는 CoreML과 CPU입니다. 연산별 실행 장치 전체가 GPU나 ANE라는 주장은 하지 않습니다.
Q. 개발이 어디까지 되었나요?
A. 실행 가능한 Mac 앱, 세 운동의 반복 계산, 부분 촬영, 대상 고정과 진단 화면, 자동 테스트 및 실제 표본 영상 검증까지 완료했습니다. 다양한 환경의 일반 정확도 검증과 배포용 독립 패키징은 후속 과제입니다.

실행
프로젝트 루트에서 ./run.sh
또는 프로젝트 내부의 Local Motion.app 더블클릭. 이 런처는 현재 프로젝트의 Python과 모델 경로를 사용하므로 다른 Mac에 복사만 해서 실행하는 독립 설치 앱은 아닙니다.
