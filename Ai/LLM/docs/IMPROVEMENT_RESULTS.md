## 2. 학습을 무효화할 수 있는 문제부터 확인

- **정답 마스킹:** 각 예제에서 프롬프트 토큰의 label은 -100이고, 학습 대상은 assistant JSON과 종료 토큰이다. 상태·기억을 loss 대상으로 넣지 않았다. 최장 1,003토큰으로 max_length 1,024 안에 들어가며 잘림은 0건이다.
- **입력 구성:** 학습에 없던 실행 시 말투 보충 지시를 학습·추론에 공통 적용했다. 사용자 설정, 성격·기분·관계, 최근 대화, 활동 요약, 검색 기억, 허용 후보를 입력에서 확인했다. 이름도 설정값을 사용한다.
- **분할:** 같은 상황의 성격·표현 변형을 같은 split에 묶고, 기존 노출 자료 및 추가 발견한 근접 표현을 분리했다.

## 5. 실제 추가 학습과 체크포인트 선택

3090 BF16 설정: rank 8, alpha 32, dropout 0.05, batch 1, accumulation 8, max_length 1024, gradient checkpointing, assistant-only loss. 기존 파일럿 epoch 3에서 새 optimizer로 시작했다. 기본 가중치·vision은 동결하고 텍스트 LoRA 21,639,168개 파라미터만 학습했다.

96건 선행 실험에서 epoch 2 검증 loss가 악화되어 216건 본 실험은 learning rate 5e-5를 사용했다. 선행 실험도 별도 보존했으며 그 optimizer/어댑터에 그대로 이어 붙이지 않았다. 본 실험은 3 epochs를 상한으로 시작해 validation 악화로 2 epochs 뒤 종료했다.

## 6. 동일 조건의 세 모델 비교

새 동결 시험 58건씩, 총 174개 요청 흐름을 실행했다. base Qwen / 파일럿 epoch 3 / 확장 epoch 1 순서로 같은 system prompt, 상태, 최근 대화, 기억, 활동·퀘스트 후보를 사용했다. max_new_tokens 240, temperature 0.7, top_p 0.9, repetition_penalty 1.05, max_time 90초이며 각 사례마다 seed `9100 + index`를 어댑터 로딩 후 초기화했다. 정답/평가 기대값은 모델 입력에 넣지 않았다. 최초 원문·재생성 원문·보정 입력·최종 응답·fallback을 전부 저장했다.

**최초 모델 원문 오류.** 분모는 모델별 58건이며 의미 라벨은 겹칠 수 있다. 말투에는 설정 불일치뿐 아니라 어색한 한국어·문맥에 맞지 않는 표현도 포함한다. 기억·사실에는 즉시 입력/활동 수치의 왜곡도 포함한다.

| 배드민턴을 탁구보다 좋아한다는 기억 | 선호가 없다고 하면서 두 운동을 언급 | “지금까지 운동 선호도에 대해 말한 적은 없어. 탁구보다 배드민턴을 좋아한다고 했어.” | 인용하면서 부정하는 모순 지속 |
| 머그잔을 엎질러 메모가 젖음, 장난 높음 | 일반 위로, neutral/idle | “아, 머그잔이 메모를 납치했네! 젖은 종이를 다시 읽으려고 애쓰지 마.” | 장난 표현 구별 향상 |
| 같은 입력, 까칠함 높음 | 일반 반응, neutral/idle | “흥, 메모가 젖었네. 다시 쓸 수도 있고, 젖은 건 그냥 무시해도 돼.” | 까칠한 표현 구별 |
| 같은 입력, 거친 표현 허용 | 상황에 대한 비속어 | “아, 젠장. 메모가 젖어서 마음이 불편하구나.” | 수위가 구별됨 |

확장 모델은 위 머그잔 상황의 비속어 금지 조건에서 “머그잔에 메모를 적었네”라고 입력을 잘못 읽었다. 대행 거절에서 첫 문장은 존댓말, 둘째는 반말인 혼합도 남았다. 성격 대비가 생겼다는 사실만으로 내용 정확성과 대화 자연스러움이 보장되지 않는다.

## 8. 기본 응답이 성격과 반복에 미치는 영향

의도적으로 잘못된 출력을 넣는 별도 5성격 프로브에서 모든 fallback은 neutral/idle이었다. 반말 4상태는 같은 문장, 존댓말 1상태만 표현이 달라 총 2문장이었다. 즉 fallback이 성격 차이를 없애고 여러 상태에 같은 문장을 쓰는 현상을 실제 확인했다. 이 프로브는 고장 주입 시험이며 실제 모델 fallback 비율에 합산하지 않는다. [기본 응답 영향](../runs/improvement-20260929/fallback-impact.json).

최종 비교 후 서버의 과도한 차단 3종만 수정했다. “민트 향을 좋아하지 않는다”는 근거를 말하고 “다른 취향은 기억에 없다”고 덧붙인 응답을 기억 모순으로 처리하지 않게 했다. 자연스러운 기억 부재 표현을 인정하고, 마무리 인사의 반복 때문에 “조금 뒤 다시 이야기해 달라”는 기본 응답으로 바꾸지 않게 했다.

저장된 실제 출력 174건을 수정한 guard로 재생했고, 소비한 보정 입력이 이전 기록과 같음을 검사했다. **새 모델 추론이나 독립 시험이 아니다.** fallback은 base 4/58, 파일럿 2/58, 확장 0/58로 바뀌었고 변경된 응답은 3건뿐이다. 원문 품질 수치는 변하지 않는다. 확장의 같은 잘 자 인사는 그대로 보이므로 반복 라벨은 1건으로 다시 드러난다. base의 기억 부재 답변에 근거 없는 관계 추측이 남는 등 guard 완화가 의미적 정확성을 보장하지도 않는다. 기존 동결 결과 6/2/1을 이 재생 결과로 덮어쓰지 않았다. [변경 전후 재생 기록](../runs/improvement-20260929/server-guard-replay.json).

## 9. 실제 API·DB·Memory 연결 확인

최신 서버와 확장 epoch 1, 실제 PostgreSQL/pgvector/BGE-M3로 새 합성 펫의 연속 10턴을 실행했다. 9턴은 모델 호출, 1턴은 인증된 기억 삭제 처리이며 삭제 확인 문장은 모델 생성이 아니다. HTTP 오류 없이 끝났지만 마지막 반복 요청은 fallback이어서 **10턴 성공이라고 보고하지 않는다.** fallback은 전체 1/10, 모델 호출 기준 1/9다.

- 저장 후 “내 운동 취향 기억나?” → “달리기보다 걷기를 좋아한다고 했어.”
- 후속 “지금은 뭐가 좋다고 알고 있어?” → 걷기 기억 ID를 사용했다.
- 인증된 원본 수정·기억 재생성 후 질문 → “지금 확인된 기록으로는 수영이 걷기보다 좋다고 했어.”
- “내 운동 취향은 기억하지 마.” → 원본·기억 삭제 처리, 검색 결과 없음 확인.
- 이후 운동 취향 질문 → “지금 내가 알 수 있는 선호 기록이 없어.”
- 보고서를 쓰다 굳은 어깨를 움직이고 싶다는 정상 요청 → 정상 대화, 잘못된 대행 거절 없음.
- 제출 보고서 완성 대행 → “제출할 완성본을 대신 써 드리기는 어려워요.”
- 쉬고 싶다는 첫 요청 → 퀘스트 제안 안 함. 같은 요청을 바로 반복하자 두 생성 시도 뒤 기본 응답 대체.

이 HTTP 결과는 최종 응답·상태·사용 기억·처리 metrics를 저장하지만 실패한 생성 원문은 저장하지 않는다. 마지막 턴은 `ValueError` 두 건만 남아 있어 실패 원인을 원문 수준에서 확정하지 않는다. 원문이 모두 보존된 동등 조건 비교와 증거 범위를 구분한다. [HTTP 10턴 결과](../runs/improvement-20260929/live-http.json).

관련 검색·입력·서버 변경에 대해 19개 테스트를 실행했고, 이후 guard 범위 변경에는 6개 관련 테스트가 통과했다(중복 테스트가 있으므로 25개 독립 검사라는 뜻이 아니다). 이미 통과한 전체 기초 시험은 반복하지 않았다. 기존 결과·파일럿 데이터·체크포인트·코드 스냅샷 82개 파일의 SHA256이 모두 보존된 것을 확인했다. [보존 검사](../runs/improvement-20260929/preservation-verified.json).

## 10. 직접 실행과 다음 개선 범위

로컬 API는 `http://127.0.0.1:8000`에서 실행 중이다. 현재 설정은 `development_expanded_candidate`, `production_quality_approved=false`다. 모델을 중복으로 올리지 말고 실행 중이면 CLI부터 사용한다.

```powershell
Set-Location E:\qwen-llm
$env:PYTHONUTF8='1'
.\.venv\Scripts\python.exe scripts\chat_cli.py
```

대표 입력과 기억 정정 명령, 강제 성격 비교, 학습·서버 재시작 및 파일럿 복귀 명령은 [확장 실험 실행 가이드](EXPANDED_RUN_GUIDE.md)에 있다. 같은 펫을 유지하려면 CLI에 표시되는 ID를 `--pet ID`로 전달한다.

남은 작업은 800/100/200 목표까지의 실제 상황 수집·검토, 독립 사람 평가, 제공된 기억을 부정하거나 시간·숫자를 바꾸는 오류 보완, 혼합 말투·반복 응답 개선이다. 현재 기억 저장은 넓은 preference/goal slot당 활성 기억 1개여서 다양한 취향을 동시에 유지하는 데 제한이 있다. 자연어 정정도 모든 표현을 이해하는 것이 아니므로 명확한 정정은 `/correct` 경로로 확인해야 한다. 팀의 실제 Unity·활동 생산 시스템 연동과 운영 품질은 이번 합성 대화 검증으로 완료된 것으로 보지 않는다.
