## 원인별 조치

* 검색: 실제 BGE/pgvector 재현에서 수영 취향 후 '지금은 뭐가 좋다고 알고 있어?' 점수는 0.454라 누락, 무관한 날씨는 0.568이라 통과했다. 명시적 취향/목표 질문과 바로 앞 사용자 질문의 주제로 검색 슬롯을 좁히고, 일상 대화에는 무관한 기억을 주입하지 않는다. 소유권·유효 source revision 검사는 유지한다. `retrieval-before.json`과 실제 DB 테스트가 근거다. 현재 슬롯별 한 개의 취향이라는 기존 저장 모델은 여전히 제한이다.
* 입력: 학습 `messages`에는 말투 보조 지시가 빠지고 추론에는 있었다. 이제 같은 함수를 기본 설정으로 사용한다. 이름을 몽글이로 고정했던 지시를 설정 이름으로 바꾸고, 활동 합계/최신 기억/사용자 직접 발언을 구별했다.
* 검증: 운동 기록이 있어도 memory가 비면 부재 응답을 강제하던 조건을 분리했다. 무관한 최근 취향이 별명 기억의 근거로 인정되던 조건도 분리했다. 이는 모델 실패를 서버가 만들던 사례다.
* 재생성: 실패한 assistant 원문과 오류를 함께 전달한다. 두 번째 응답에도 불필요한 문장 중복 검사를 적용한다. 사실 재확인은 반복 회피 대상에서 제외한다. 의미상 반복은 단순 문자열 비교로 완전히 잡을 수 없다.
* 퀘스트: 쉬고 싶음/권유 거절 입력에는 후보를 제거한다. 후보 권한과 모델의 말투는 각각 검사한다.
* 데이터: 근거가 전달돼도 취향 대신 쉬라고 답한 사례, 까칠함이 모욕으로 바뀌는 사례, 비자연적 한국어, 반복 거절을 데이터 보완 대상으로 분류했다. 서버 고정 문장을 늘려 모델 개선으로 세지 않는다.
