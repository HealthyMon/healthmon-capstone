# 현재 epoch 1 LoRA의 Persona 의미 검토

검토일: 2026-10-01. **36개 A/B 쌍, 72개 최종 출력의 입력 상태·선택 후보·원문·수정 과정을 검토했다.** 10개 비교 × 3개 seed와 여섯 30일 시나리오의 Day 0/30 비교 × 1개 seed다. 이 문서는 코딩 에이전트가 실제 원문을 읽은 독립 의미 검토이며, 사람 평가자의 점수나 통계적 품질 보증이 아니다.

**판정 B: 현재 LoRA가 네 성격축별 말투를 충분히 구분한다고 보기 어렵다. C: 네 축 대조 데이터 제작과 추가 학습을 권고한다.** 호기심과 모든 축을 동시에 바꾼 조건에서 일부 구조 차이는 나타났다. affection·confidence의 독립적인 효과는 약했고, 같은 퀘스트 ID를 내면서 다른 활동이나 시간을 설명하는 문제와 과거 기록의 날짜 왜곡이 남았다. 규칙 엔진의 정상 선택과 모델 대사의 의미 정합성을 별도로 판정했다.

## 평가한 대상과 통제 범위

대상은 로컬 `Qwen3.5-9B`와 `runs/expanded-20260929/checkpoint-epoch-1`에 새 네 축 Prompt, 계산된 style profile, 규칙 Quest Selector를 함께 적용한 시스템이다. 기존 데이터의 새 네 축 직접 사례는 train 0/216, validation 0/43, test 0/58이다. 기존 LoRA는 7축 자료로 학습됐다. 이번 결과를 네 축을 LoRA가 학습했다는 증거로 해석하지 않는다. 베이스 모델 단독 또는 기존 Prompt를 둔 대조군도 없다.

10개 비교에서 각각 seed 20261001, 20261002, 20261003을 사용했다. 각 A/B의 입력·memory·seed·생성 파라미터는 같고, 모든 memory 입력은 빈 목록이었다. `max_new_tokens=240`, `temperature=0.7`, `top_p=0.9`, `repetition_penalty=1.05`, `max_time=90`이다. Repair는 seed에 시도 순번을 더하므로 수리가 발생한 쌍의 최종 문장이 같은 첫 seed에서 한 번씩 나온 것은 아니다.

후보 Quest도 성격에 따라 달라지는 비교가 많다. 따라서 음식 기록 대사와 걷기 대사가 달라졌다는 사실만으로 말투 학습 성공을 선언할 수 없다. 같은 후보를 둔 confidence 단독 비교가 특히 중요하며, 여기서는 차이가 약했다. Day 0/14, 음식 이력, 성공/실패 비교는 성격·단기 상태·근거·후보가 함께 달라지는 전체 시스템 비교다.

## 실행 결과와 형식 검증

전체 72개 출력 중 최초 원문 통과 67개, repair 후 반환 4개, fallback 1개다. 최종 Qwen 대사로 의미를 검토할 수 있는 응답은 71개이며, 두 쪽 모두 Qwen 대사인 완전한 쌍은 35개다. fallback은 모델의 성격 표현 능력 평가에서 제외한다. 67개가 `neutral/idle`, 3개가 `encouraging/encourage`, 1개가 `playful/wave`, 1개가 `happy/wave`였다. 다양한 성격·기분이 표정/애니메이션으로 충분히 표현됐다는 근거는 약하다.

한 출력은 첫 생성이 JSON 끝까지 나오지 않아 repair를 거쳤고 163.75초가 걸렸다. 이것은 실행 지연과 출력 절단의 증거이며, 그 첫 원문을 의미상 잘못된 정답으로만 분류하지 않는다. 작은 반복 실험에서도 지연 편차가 있으므로 모든 비교가 즉시 완료된다고 보장할 수 없다.

처음 30쌍을 저장한 뒤 첫 Day 0/30 요청이 HTTP 360초 제한에 걸려 평가 프로그램이 중단됐다. 기존 30쌍은 보존하고 로컬 서버를 재시작했으며, 생성 사이에 `torch.cuda.empty_cache()`를 호출하도록 한 뒤 남은 6쌍만 추가했다. 가중치·dtype·Prompt·생성 파라미터는 동일하게 유지했다. 저장되지 않은 timeout 요청을 성공한 평가 결과로 포함하지 않았다. 재시작 후 한 요청을 다시 실행한 raw attempts는 A/B 모두 최초 기록과 동일했다. 이는 이번 모델·GPU·설정에서의 관측이며, 환경 간 또는 모든 입력의 완전한 재현성을 보장하지 않는다.

### curiosity_20_vs_80

질문/추가 요청은 high 쪽 3/3에서 늘지만, 새 관점의 비교는 불안정하다. low는 2문장 안팎의 수용/여지를 남기는 답, high는 음식의 맛·이유나 다른 활동을 묻는 확장이다. 단순 어미 차이를 넘는 일부 구조 차이가 있다.

- high 0은 새로운 경험 요청을 이미 먹은 음식의 회상으로 돌린다.
- high 2는 질문과 무관한 검증된 기록 부재를 첫 문장에 넣는다.
- 후보도 food_record_1에서 new_food_1로 바뀌어 순수 말투 효과와 후보 내용의 영향을 분리할 수 없다.

### affection_20_vs_80

high의 관심 질문은 3/3지만 따뜻함/친밀감 자체는 약하고 curiosity와 얽힌다. low도 이미 공감적이다. high는 그림에 대한 감상 질문을 덧붙이나 함께한다는 정서적 지지나 문장 구조의 독립적인 차이는 작다.

- repeat 1 high는 편안한 마음으로 감상했다고 입력에 없는 감정을 가정한다.
- repeat 1 low의 다녀오셨구나는 지정된 편안한 반말 안에서 존대 요소가 섞인 표현이다. 명확한 존댓말 종결 혼용 사례와는 구분한다.
- 후보가 음식 기록에서 동행 걷기로 변경되어 성격 축만의 설명력은 제한된다.

### activity_20_vs_80

high 3/3이 2분 스트레칭을 설명한다. low는 2/3에서 음식 기록 action과 운동 speech가 불일치한다. high가 명시적 활동을 먼저 제시하는 경향은 있으나 실행 순서/적극성 차이보다 카탈로그 후보 변경이 차이를 설명한다.

- low repeat 1은 걷기/스트레칭을 말하며 food_record_1을 offer한다.
- low repeat 2는 숨 차는 활동을 말하며 food_record_1을 offer한다.
- high repeat 2는 불필요한 검증 기록 부재 안내를 붙인다.

### confidence_20_vs_80

3회 모두 양쪽에서 편하게/천천히/보자 구조가 반복되며 결단력 차이는 안정적이지 않다. repeat 0 high의 추천해라는 결론 표현은 차이가 있지만 다른 두 번은 몸 부위/자세만 바뀐 비슷한 제안이다.

- 후보가 양쪽 동일하므로 다른 축에 비해 말투 독립 효과를 평가하기 좋지만 결과가 약하다.
- high repeat 1의 숨을 죽이고는 불필요하고 부적절한 운동 지시 표현이다. 의료적 안전성을 검증한 결과는 아니다.
- 검증 안 된 사실을 높은 자신감 때문에 더 확실하게 단정한 명백한 사례는 이 세 입력에서 관찰하지 못했다.

### all_20_vs_80

high는 3/3 걷기 목표와 2~3문장 설명, low는 짧은 기록/휴식 제안이다. 일부 high 응답은 결론-이유-첫 단계 구조와 encouraging/playful 표정을 보인다.

- 후보가 음식 기록에서 100걸음으로 바뀌었다.
- high curiosity인데 질문은 한 번만 나타나며 warmth 차이도 강하지 않다.
- 모든 축을 동시에 바꿔 어느 축이 어떤 차이를 만들었는지 특정할 수 없다.

### activity80_confidence80_vs20

repeat 1에서는 high가 결론-이유-단계로 더 명확하지만 repeat 0/2는 양쪽이 비슷한 부드러운 제안이다. 높은 활동성을 유지한 낮은 자신감 조합을 안정적으로 구현했다고 보기 어렵다.

- repeat 1 low는 catalog의 2분 스트레칭을 offer하면서 1분만 움직이라고 설명한다. 초기 단계 안내로 해석할 여지도 있지만 전체 목표를 알려주지 않아 표시 목표와 대사가 충돌한다.
- 낮은 자신감 측의 에너지가 많으니라는 표현은 사용자의 실제 에너지에 대한 검증 사실로 취급하면 안 된다.

### affection80_neutral_vs_low

첫 두 쌍은 low의 조용하거나 무거운 기분과 친근한 태도를 함께 유지한다. 세 번째는 두 쪽 모두 잠들기 전이라는 근거 없는 설정을 붙인다. low일 때 사용자를 밀어내거나 무례하게 변하지 않는다. 다만 emotion/animation은 전부 neutral/idle이다.

- 3회차 양쪽에 근거 없는 캐릭터 취침 상태 추가.
- 3회차 low의 첫 원문은 follow_up_question 추가 필드 때문에 거절되고 동일 대사가 schema repair 후 반환됐다.

### day0_vs_exercise14

Day 14의 cycle_5 후보를 2/3회 설명하지만 1/3회는 후보가 있는데도 추가 퀘스트가 없다고 답한다. 목표가 음식 기록에서 5분 자전거로 바뀐 것은 selector의 규칙 결과다. 문체는 대부분 같은 중립 제안 구조다.

- repeat 0 Day 14 원문은 활성 퀘스트가 없는데 남은 걸음이 없다고 말해 guard가 차단했다.
- 수정 응답의 오늘 추가할 퀘스트는 없어는 실제 후보 cycle_5와 모순되지만 최종 검증을 통과했다.
- 장기 성격 변화뿐 아니라 기분·에너지·성공 기록·후보가 함께 바뀌므로 순수 personality 학습 효과로 귀속할 수 없다.

### varied_vs_repetitive_food

다양한 식생활 쪽 1회가 activity event_id를 memory_ids에 인용해 fallback. 나머지 2쌍은 식사 기록 요약 후 카탈로그 후보를 설명한다. varied는 음식 기록 후보, repetitive는 새 음식 후보다. 이는 최근 식생활을 사용하는 selector의 동작이며 말투 구조는 둘 다 요약-제안이다.

- repeat 0 varied는 6개 활동 event_id를 memory_ids에 넣어 길이 초과, repair에서도 3개 잘못된 ID를 남겨 guard가 차단했다. 최종 대체문장은 실제 모델 말투 비교에서 제외한다.
- 원문은 음식 기록을 한 끼로 확장해 설명한다. 기록된 음식/1회분과 실제 한 끼를 동일하게 단정하면 안 된다.
- 최종 응답의 지난 6일은 prompt가 보여준 최근 여섯 행을 요약한 것으로, 전체 30일 분석으로 해석하면 안 된다.

### quest_success_vs_failure

성공 쪽은 food_groups_2, 실패 쪽은 walk_100을 규칙으로 선택하지만 성공 repeat 1은 후보를 무시한다. 검증 성공에 따라 난이도 2, 실패 이력에서는 난이도 1로 선택된다. 말투는 양쪽 모두 유사한 중립 제안이다.

- 성공 repeat 1 원문이 미선택 walk_100과 10분 걷기를 생성해 guard가 Unauthorized quest로 거절했다.
- 그 repair 응답은 검증된 퀘스트가 없다며 현재 food_groups_2 후보를 설명하지 않는다.
- 실패 repeat 0의 수락 없이 확인할 수 있다는 말은 후보 열람을 뜻할 수도 있다. 실제 수락 없이 완료된다고 단정한 증거로 과장하지 않는다.

## 여섯 30일 시나리오의 실제 Day 0/30 응답

여섯 Day 0 응답은 같은 입력·seed·상태를 사용하여 모두 동일했다. “네, 몽글이는 지금 네 이야기를 조용히 듣고 있어…”라고 답했고 작은 도전은 제안하지 않았다. 이 동일 출력은 재현 결과이며, 여섯 개의 독립적인 성격 표현 성공/실패 증거로 합산하지 않는다. Day 30은 상태별 한 번씩만 생성했으므로 일관성 판정에는 부족하다.

| 시나리오 | Day 30 후보 | 실제 대사와 의미 판정 |
|---|---|---|
| 꾸준한 운동·성공 | 음식군 2개 기록 | 목표→응원→첫 단계 구조, happy/wave 차이가 관찰됐다. 후보·기분·근거도 바뀌어 장기 성격 학습의 독립 효과로 귀속할 수 없다. |
| 초반 운동 후 중단 | 새 음식 1개 기록 | 후보를 설명하나 “수용해.”로 시작하며 최근 2주 중단에 따른 배려가 뚜렷하지 않다. |
| 새로운 운동·음식 | 음식 1개 기록 | 최근 수영·춤·요가 및 두부·연어를 활용한다. 각각 다른 날짜의 운동을 “매일” 했다고 묶은 요약은 빈도를 과도하게 일반화할 여지가 있다. |

| 잦은 실패·꾸준한 대화 | 100걸음 | 자발적인 시작을 제안하나 정확한 100걸음 목표는 대사에서 생략한다. 후보 UI에는 올바른 값이 있다. |

여섯 Day 30 중 세 대사가 “수용해.”로 시작했다. 서로 다른 성장 이력이 이런 같은 딱딱한 문장으로 귀결되는 것은 자연스러운 게임 캐릭터 대사가 충분히 안정화됐다는 증거가 아니다. 식생활 시나리오의 “오늘의 이야기는 … 네 말에서 시작했네”는 과거 인용을 오늘 대화의 출발점으로 삼았다는 해석도 가능하므로, 위의 명백한 29일 날짜 왜곡과 같은 확정 오류로 세지 않았다.

## 최종 대사에 남은 중요한 문제

- `activity_20_vs_80`, repeat 1/2, A: `action=offer_quest(food_record_1)`인데 걷기·스트레칭 또는 숨 차는 활동을 설명한다. ID 허용 검사에는 통과해도 speech와 사용자에게 제시되는 퀘스트가 다르다.
- `activity80_confidence80_vs20`, repeat 1, B: 카탈로그는 2분 스트레칭인데 “처음엔 … 1분만”이라고 말하며 같은 퀘스트를 제안한다. 초기 단계 안내일 여지는 있지만 전체 2분 목표를 설명하지 않아 사용자에게 목표를 다르게 전달할 수 있다. 실제 카탈로그 값이나 보상이 변경된 것은 아니다.
- `day0_vs_exercise14`, repeat 0, B: `cycle_5` 후보가 존재하지만 “오늘 추가할 퀘스트는 없어”라고 말한다. 첫 원문의 남은 걸음 주장은 guard가 막았으나 repair의 후보 부정은 통과했다.
- `quest_success_vs_failure`, repeat 1, A: 미선택 퀘스트 원문을 guard가 막은 뒤 “검증된 퀘스트가 없어. … 새로운 목표를 제안하지 않을게”라고 답한다. 활성·완료 기록과 현재 제안 후보를 구분하지 못한 것으로 보인다.
- `scenario_day0_day30:repetitive_exercise_quiet`, B: 29일 전 독서 대화를 오늘의 일로 바꾼다. Prompt에 원래 `occurred_at=2026-10-01T18:00:00+09:00`와 현재 `as_of=2026-10-30T23:59:59.999999+09:00`가 모두 있었으므로, 근거가 없어서 발생한 문제는 아니다.

단정의 강도가 낮은 문제도 구분했다. 그림을 편안한 마음으로 봤다는 감정 추정, 입력에 없는 캐릭터의 취침 직전 설정, “숨을 죽이고”라는 불필요한 운동 지시 표현이 있었다. 이것들을 확인된 기억 위조·보상 지급·의학적 위해 발생으로 과장하지 않는다.

## 차단된 원문과 최종 결과의 구분

| 사례 | 원문 문제 | 실제 최종 결과 |
|---|---|---|
| mood low repeat 2 | `follow_up_question` 추가 필드 | 같은 대사를 정상 schema로 repair |
| Day 14 repeat 0 | 활성 수락이 없는데 남은 걸음이 없다고 표현 | repair 후 후보가 없다는 다른 의미 오류가 남음 |
| 다양한 음식 repeat 0 | 활동 event_id 6개를 memory_ids에 사용; repair에서도 잘못된 ID 3개 | fallback. 모델 대사 평가에서 제외 |
| 성공 이력 repeat 1 | 미선택 `walk_100`과 10분 걷기 생성 | Unauthorized quest로 차단; repair는 후보를 무시 |
| 성공 이력 repeat 2 | 첫 JSON이 중간에서 끝남 | repair 성공; 최종 음식군 2개 목표는 일치 |

최종 결과에서 보상을 지급했다는 명확한 단정이나 허용되지 않은 `memory_ids` 인용은 관찰하지 못했다. 그러나 **과거 대화의 날짜 왜곡은 실제로 관찰했다.** memory 목록은 모두 비어 있고, 명시적인 기억 질의·미검증 완료 주장에 대한 적대적 입력도 충분하지 않다. “없는 기억을 만들지 않는다” 또는 “완료 주장을 항상 검증한다”는 능력을 입증한 시험은 아니다. 실제 상태 변경은 규칙 계층이 결정하며, 이번 모델 응답이 실제 DB나 보상을 바꾼 것은 아니다.

## 자동 관측값과 의미 판정은 다르다

`?` 개수와 글자 수는 자동 관측이다. curiosity low/high의 물음표 합계는 0/2, 평균 글자 수는 57.0/97.7이지만 “어떤 생각인지 궁금해” 같은 정보 요청은 물음표 없이 나타난다. affection high 세 응답도 물음표는 0개지만 모두 추가 감상을 요청한다. 따라서 물음표 수를 질문 빈도나 친밀감 점수로 동일시하지 않았다.

activity high의 평균 길이는 43.7자로 low의 51.3자보다 짧다. 짧다고 더 소극적이거나 길다고 더 적극적인 것은 아니다. confidence low/high의 52.3/61.3자 차이도 독립적인 확신 표현 성공을 뜻하지 않는다. “편하게”, “천천히”, “보자”에 머무는 구조와 실제 선택 설명을 함께 읽었다.

전체 72개 중 11개 대사에 “검증”이라는 말이 나왔다. 기록을 돌아보라는 입력에는 필요한 경우도 있지만, 새로운 주말 활동 추천 같은 일반 대화에서 구현상의 기록 조건을 먼저 설명하는 것은 캐릭터 대사 품질을 해친다. “검증된 두부나 연어”는 섭취 기록 검증을 음식 자체의 성질처럼 표현한다. 내부 파일 경로나 서버 비밀이 노출된 것은 아니며, 제품 문장에 구현 논리가 드러나는 현상으로 분류한다.

## 다음 개선의 분리

1. 규칙·출력 연결: Quest ID만 검사하지 말고 선택한 활동·목표·단위를 표시와 연결한다. 숫자/단위가 중요한 목표 문구는 규칙에서 고정 렌더링하는 방식을 우선 검토한다. 완료/보상은 계속 규칙으로만 처리한다.
2. Prompt/Context: `candidates`, `active_quests`, 검증된 기록, `memory_ids`의 역할을 더 명확히 구분한다. 활동 ID를 memory ID로 인용하지 않도록 하고, 사용자가 묻지 않은 검증 내부 설명을 줄인다. 후보가 없다는 repair가 실제 후보 목록과 충돌하면 통과시키지 않는다. 대화 기록에 오늘/과거 구분을 명시하고, 오래된 기록을 오늘의 일로 요약하는 오류를 따로 평가한다.
3. 데이터·LoRA: 같은 입력·memory·고정 후보를 유지하며 한 축만 바꾼 대조쌍을 만든다. curiosity는 질문/새 관점, affection은 질문 수와 독립적인 정서 거리, activity는 강요 없는 실행 제안, confidence는 사실 확실성과 분리된 결론/선택 표현을 훈련해야 한다. 중간 단계, 낮은 mood와 높은 affection, 실패 후 높은 activity 등 조합도 필요하다.
4. 후속 평가: 새 입력으로 축별 여러 상황을 반복하고 사람 검수를 추가한다. 같은 후보의 style-only 평가와 실제 selector를 포함한 전체 시스템 평가를 나눈다. 베이스 대 LoRA, 기존 대 새 Prompt를 비교하면 현재 차이가 어디서 오는지 더 잘 구분할 수 있다.

추가 학습의 효과나 목표 점수는 이번 실험으로 보장하지 않는다. 데이터 수량/분할 제안은 [데이터 감사](E:/qwen-llm/docs/persona-data-audit.md)를 따르며, 이번 작업에서 데이터를 대량 생성하거나 LoRA 학습을 실행하지 않았다.
